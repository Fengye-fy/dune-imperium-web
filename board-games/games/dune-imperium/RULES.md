# 沙丘：帝国规则依据

本模块以 2020 年《Dune: Imperium》基础版的三至四人流程为依据。`base-dev-v3` 包含基础版牌库及八名领袖；`expansions-dev-v4` 按建房选项接入 Rise of Ix / Immortality。均为待用户测试的开发实现，实际能力与执行顺序边界以 `manifest.limitations` 和接口契约为准；不包含《起义》、Epic、Go to 11 或 House Hagal。

## 简要流程

玩家用手牌派遣特工，收集水、香料和索拉里，积累势力影响力并扩充牌组。每轮依次进行开始、玩家行动、战斗、沙虫产香料与召回。开始时翻开冲突并抽五张牌；轮流派遣特工或展示剩余手牌，展示后结束本轮行动。展示所得说服力用于购牌，新牌通常进入弃牌堆。战斗比较参战兵与展示剑的战力，按名次发奖；参战兵结算后回供应区。势力影响力和同盟也是得分途径。轮末有人达到十分或冲突牌耗尽时进入终局，处理终局效果后比较分数。详见下列官方来源。

## 官方来源与核查入口

- [Dire Wolf 资源页](https://direwolfdigital.com/dune-imperium/resources/)：区分基础版、Uprising 和扩展。
- [基础版官方规则 PDF](https://d19y2ttatozxjp.cloudfront.net/pdfs/DUNE_IMPERIUM_Rules_2020_10_26.pdf)：印刷页 3–5 为组件与设置；7 为势力；8–13 为轮次与结算；16 为图标。PDF 第 17–18 页附完整行动格指南，第 19–20 页为单人/双人规则。
- [官方 FAQ，2025-01-13](https://dwd-web.s3.us-west-2.amazonaws.com/pdfs/DUNE_IMPERIUM_FAQ_25-1-13.pdf)：第 1 页同盟转移，第 2 页终局、Foldspace 与阴谋，第 3 页展示时抽牌与效果费用。该 FAQ 混有扩展条目，接入时必须按版本筛选。

起始牌与储备牌的个别图标另通过实际牌面核对：[起始牌图片入口](https://www.skiptherulebook.com/games/dune-imperium)、[Foldspace 牌面](https://dunecardshub.com/images/dune-imperium-other-foldspace.webp)。本轮已从 [Dune Cards Hub](https://dunecardshub.com/) 下载基础版的 113 张不同卡面及 22 张行动格图片，来源逐张记录在 `catalog-base.json` 和静态 manifest；第三方托管不代表发行商对本项目实现的认可。规则冲突以官方规则、FAQ 和实际牌面为准。

检索日期：2026-11-09。规则名称的中文译法仅用于产品说明；稳定标识使用英文 ID。

已应用 FAQ 第 2 页的最后平分判定：分数、香料、索拉里、水和驻军均相同时，平分者中最近进行展示回合者获胜。引擎以 `lastRevealSequence` 记录展示先后，并在终局排序中最后比较此值。

## base-dev-v3：本轮补齐的内容

新局恢复 43 种/67 张帝国牌、34 种/40 张阴谋、18 张冲突和 8 名领袖。开始后先逆序选择不同领袖；男爵在第一轮前秘密选择两个不同势力，完成设置后再抽五张起始手牌。源码已补齐，测试按用户约定留给用户执行。

| 新增帝国牌 | 执行要点 |
| --- | --- |
| Kwisatz Haderach | 指定本人特工从供应区或棋盘派遣；可进入已占用格，但不能绕过 Voice、费用、影响力门槛或一次性升级限制 |
| Reverend Mother Mohiam | 有另一张 BG 在场时，对手从左侧起依次选择弃两张手牌；不足时尽量执行 |
| Shifting Allegiances | 可支付 2 香料并真实失去 1 影响力，再在任一势力获得 2；可选同一势力，同盟失去与转交先结算 |
| Test of Humanity | 对手依次选择弃一张手牌或损失一名参战兵，只列出其实际可执行的选项 |
| The Voice | 选择行动格，阻止对手进入，直到施放者下一次行动开始；不因普通占位忽略能力失效 |

| 新增阴谋 | 执行要点 |
| --- | --- |
| Bindu Suspension | 仅行动开始前可用，抽一张牌后立即交棒，不消耗特工 |
| Bypass Protocol | 免费获得印刷费用至多 3 的牌，或支付 2 香料获得至多 5 的牌并置于牌库顶；获得奖励照常执行 |
| Demand Respect | 独胜后选择任一势力 +1，或支付 2 香料在一个势力 +2 |
| Infiltrate | 本回合下一名特工可忽略敌方占位，不能忽略己方占位、Voice 或入场条件 |
| Poison Snooper | 私密查看真实牌库顶后抽取或销毁；空牌库不提前洗牌，展示时抽到的牌立即公开 |
| To the Victor… | 独胜后获得 3 香料，可再用于 Demand Respect；并列第一不算独胜 |
| Urgent Mission | 选择并召回自己一名已派出的特工，更新真实占位；展示后不重新获得特工回合 |

八名领袖的设置、被动与戒指技能定义在 `leaders.js`。Baron 的秘密选择在使用前只给本人；Paul 的牌库顶只给本人。Ilban 仅在支付行动格印刷索拉里费用时抽牌，不能由卡牌内费用触发；抽牌顺序可选择。Ariana 只对产香料格的总收获扣一次香料并抽牌；Leto 修正议会格入场费用。Memnon 在取得议会席位时提升影响力；Rabban 在设置时加资源，并按是否持有同盟决定戒指招募量。Helena 只忽略敌方议会/城市占位，操纵的牌保留给本人，展示结束未购则移出游戏。

本轮对照官方规则第 13 页核对了 Bindu、Kwisatz、Paul/Poison、Test of Humanity 和 Voice；对照 FAQ 第 1、3、4 页核对了同盟下降、海伦娜的获取方式、展示抽牌、同回合新兵和独胜阴谋时机。任一阴谋在结算完成前放在 `resolvingIntrigues`，避免被过早洗回；延迟展示的阴谋仍保留在 `activeIntrigues`。

`agentPositions` 记录实际特工，`occupied` 只保留兼容摘要。特工回合以 `endAgent` 明确结束，允许拿到新 Plot 后继续使用；部署可分批，按本回合实际招募、已部署及原驻军额度计数。独胜后以 `passCombatWin` 关闭响应窗口。选择、暂停的效果栈、对手响应和领袖私密状态均可 JSON 存档与重连。

## 旧 base-subset-v2 的录入范围

- 已开始的 v2 存档使用 38 种/60 张帝国牌、27 种/32 张阴谋，不自动补入 v3 新牌和领袖；保留原 10 张起始牌组成与 24 张储备。
- 18 张冲突按 4 张 I、10 张 II、4 张 III 分类；每局随机 1/5/4，共 10 轮上限。注意来源站把 Raid Stockpiles、Battle for Arrakeen、Grand Vision 的等级写错，项目使用 II、III、III。
- 全部冲突奖励已录入，包括“选择两项”不得重复、任意势力一次 +2、控制权、可选销毁和下一轮门泰特。帝国盆地 III 的第二/三名奖励按牌面为 5/3 索拉里，不能采用部分第三方表中的香料。
- Carryall 的展示是 1 说服力和 1 香料；Duncan Idaho 展示为 1 水和 3 剑。按牌面核对，避免误抄第三方说明。
- FAQ 的 Missionaria Protectiva 势力勘误已使用 Bene Gesserit；Guild Bankers 对本次展示的每张 The Spice Must Flow 都折扣；Assassination Mission 的销毁收益与 Imperial Spy 以自身技能销毁的条件分开处理。
- 展示效果可逐张选择顺序并穿插购买。展示时抽牌立即公开；Charisma/Recruitment Mission 在展示清理前保持公开、暂不进入可洗回的阴谋弃牌堆。

参考图鉴与运行中的存档分开。新目录中的基础版卡面和领袖均已标记为可执行，22 张行动格图片仍是参考记录，格子规则从 `catalog.spaces` 获取。旧 `core-dev-v1` 存档按旧测试牌运行，不迁移随机牌序、资源或中途对局。

派遣可选择卡牌/格子/影响力三个整体效果的六种顺序，单张卡内部多段非选择效果仍按定义顺序处理；不是任意拆分效果的自由编辑器。本轮补源码、说明和用户可运行的回归用例，未运行测试。

## 后续实现核对清单

这些项目是验收方向，不是完成声明：

- [ ] 设置：人数差异、起始组件、冲突牌等级与抽样、储备数量。
- [ ] 行动：图标、占位、入场费用、效果顺序、可选费用、销毁来源。
- [ ] 牌组：起始牌、市场补牌、展示购牌、洗牌、私人信息边界。
- [ ] 战斗：新招募兵与原驻军的部署额度、无兵战力、并列、零战力与兵力回收。
- [ ] 势力：影响力阈值、奖励、同盟转移与失去同盟。
- [ ] 轮转：提前展示、展示后跳过、连续战斗让过、香料堆积、门泰特归还。
- [ ] 终局：轮末触发、终局阴谋、平分判定。
- [ ] 完整内容：逐张核验帝国牌、阴谋牌、冲突牌与领袖；补齐控制权、特殊触发和选择窗口。

开发顺序建议：先保证服务器对核心动作做合法性校验，再以独立效果处理器补全内容；未实现的牌或模式应在创建游戏时排除或拒绝，不能悄悄按无效果处理。前端负责展示与提交选择，最终资源、抽牌和得分均由服务器计算。
